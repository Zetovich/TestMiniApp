# ⚔️ SHADOW VAULT — Telegram Mini App RPG

Пошаговая dark-fantasy RPG в духе Raid: Shadow Legends для Telegram Mini Apps.
Вся боевая математика считается **на сервере**; клиент только рисует анимации.

> **Статус сборки:** готово полностью — `package.json`, `server.js`, `index.html`, `README.md`
> и весь пакет ассетов в `images/`. Проект запускается и проходит тесты (37/37 + 7 UI).

---

## 1. Стек

| Слой | Технологии |
|---|---|
| Сервер | Node.js 18+, Express 4, Socket.io 4 |
| БД | MongoDB + Mongoose 8 (есть fallback-режим «в памяти» для разработки) |
| Клиент | HTML + CSS + Vanilla JS, Telegram WebApp SDK |
| Ассеты | PNG с альфа-каналом (персонажи) + SVG (иконки) |

## 3. Быстрый старт

### Вариант A — без MongoDB (мгновенно, для разработки)

```bash
cd Testings
npm install
DB_MODE=memory npm start
# → http://localhost:3000
```

В этом режиме данные живут в памяти процесса. Авторизация Telegram отключена:
игрок определяется заголовком `x-dev-id` (по умолчанию `1000001`).
Откройте `http://localhost:3000` — сервер отдаст `index.html`.

### Вариант B — с MongoDB (production)

```bash
cp .env.example .env
# впишите TELEGRAM_BOT_TOKEN и MONGO_URI
npm install
npm start
```

Быстрый запуск базы локально:

```bash
docker run -d --name shadow-vault-db -p 27017:27017 mongo:7
# MONGO_URI=mongodb://127.0.0.1:27017/shadow_vault
```

### Переменные окружения

| Переменная | Описание |
|---|---|
| `PORT` | Порт (по умолчанию `3000`) |
| `TELEGRAM_BOT_TOKEN` | Токен бота — включает проверку подписи `initData` |
| `MONGO_URI` | Строка подключения MongoDB |
| `DB_MODE` | `mongo` или `memory` (по умолчанию `mongo`, если задан `MONGO_URI`) |
| `ADMIN_IDS` | ID админов через запятую (по умолчанию `8213153991`) |
| `NODE_ENV` | `production` отключает dev-вход по `x-dev-id` |

### Проверка работоспособности

## 5. Геймплей

### 5.1. Классы и стихии

| Класс | Роль | HP | Атака | Защита | Скорость | Крит / Урон крита |
|---|---|---|---|---|---|---|
| Воин | Танк, защита | 1250 | 96 | 124 | 96 | 10% / 50% |
| Маг | Урон по площади | 940 | 138 | 82 | 104 | 12% / 55% |
| Ассасин | Скорость, крит | 980 | 128 | 74 | 124 | 26% / 68% |

Стихии: **Огонь → Природа → Магия → Огонь**, плюс **Вода → Огонь**
(Вода ← Природа). Матрица без противоречий:

| | бьёт сильнее (+15%) | бьёт слабее (−35%) |
|---|---|---|
| Огонь | Природа | Магия, Вода |
| Природа | Вода, Магия | Огонь |
| Магия | Огонь | Природа |
| Вода | Огонь | Природа |

### 5.2. Боевая система (пошаговая, turn meter)

- Каждый юнит имеет `tm` (0…100) и `speed`. Время до хода = `(100 − tm) / speed`;
  кто первый — тот и бьёт. После хода `tm = 0`. Чем выше скорость — тем чаще ходы.
- **Скиллы:** 1 базовая атака + 1 активный скилл с кулдауном 3 хода.

| Класс | База | Активный скилл |
|---|---|---|
| Воин | Удар щитом (×1.0) | **Клич Бастиона** — щит 25% HP всей команде на 2 хода + себе контратака |
| Маг | Искра (×1.05) | **Волна пламени** — урон по всем (×0.85), 60% шанс яда на 2 хода |
| Ассасин | Разрез (×1.0) | **Теневой выпад** (×2.2) — игнор 50% защиты, +30% крита, −25% защиты цели |

- **Баффы/дебаффы:** Яд (тикает в начале хода носителя), Снижение защиты,
  Щит (поглощает урон), Контратака (ответ на одиночную атаку, 60% силы).
- **Формула урона:**
  ```
  mitigation = DEF / (DEF + 800)
  damage     = ATK × skillMult × (1 − mitigation) × affinity × crit × rand(0.92…1.08)
  ```
  `affinity` = 1.15 / 1.0 / 0.65, `crit` = 1 + critDmg/100.
- **Яд** = 5–6% макс. HP цели, но не более 75% атаки отравителя (защита от абуза на боссе).

### 5.3. Экипировка и прокачка

- **6 слотов:** оружие, шлем, щит, перчатки, нагрудник, сапоги.
- **4 редкости:** обычный (×1.0) / редкий (×1.35) / эпический (×1.8) / легендарный (×2.4).
  Редкость влияет на главный стат, количество подстатов (2–4) и цену кузницы.
- **Сеты:** Скорости, Атаки, Жизни. Бонусы за 2 и за 4 предмета:
  - Скорость: 2 → +12% скорости; 4 → +25% скорости, +10% атаки
  - Атака: 2 → +12% атаки; 4 → +30% атаки, +10% крита
  - Жизнь: 2 → +15% HP; 4 → +35% HP, +15% защиты
- **Кузница:** улучшение предмета за золото, до 15 уровня,
  цена = `(260 + уровень × 210) × множитель редкости`.
- **Слияние:** 3 героя одного ранга → 1 герой рангом выше (до 6★), стоимость `500 × ранг` золота.

### 5.4. Ресурсы

| Ресурс | Правила |
|---|---|
| Золото | награда за бои, тратится в кузнице и при слиянии |
| Звезды ⭐ | премиум: призыв героя (100 ⭐), восстановление энергии (20 ⭐) |
| Энергия | максимум **50**, +1 каждые **5 минут**, бой в кампании — 6 единиц |

### 5.5. Режимы

- **Кампания (PvE):** 12 этапов, живые бои через Socket.io, награда за первое прохождение.
- **Арена (PvP):** список из 5 **реальных** игроков (если живых меньше — добивается ботами),
  бой **асинхронный**: сервер мгновенно симулирует его и отдаёт лог для проигрывания,
  рейтинг по Эло (±18 за победу / −12 за поражение).
- **Босс (Raid):** ежедневный босс (общий пул HP на день), 3 попытки в сутки,
  награда зависит от нанесённого урона, есть таблица вклада.

## 6. REST API

Авторизация: заголовок `x-init-data` с `initData` из Telegram WebApp
(в dev-режиме — `x-dev-id: <id>`).

| Метод | Endpoint | Описание |
|---|---|---|
| POST | `/api/auth` | вход / создание игрока, отдаёт профиль + статичные игровые данные |
| GET | `/api/state` | полное состояние: игрок, этапы, босс, справочники |
| POST | `/api/team` | `{ team: [heroUid, …] }` — состав команды (до 4) |
| POST | `/api/item/equip` | `{ itemUid, heroUid }` |
| POST | `/api/item/unequip` | `{ itemUid }` |
| POST | `/api/forge` | `{ itemUid }` — улучшение за золото |
| POST | `/api/fuse` | `{ heroes: [3 uid] }` — слияние |
| POST | `/api/summon` | призыв героя за 100 ⭐ |
| POST | `/api/energy/refill` | +50 энергии за 20 ⭐ |
| GET | `/api/campaign` | список этапов (флаг `locked`) |
| GET | `/api/arena` | 5 соперников |
| POST | `/api/arena/fight` | `{ opponentId }` → `{ win, ratingDelta, events, rewards }` |
| GET | `/api/leaderboard` | топ-20 по рейтингу |
| GET | `/api/boss` | состояние босса дня |
| GET | `/api/health` | статус сервера |

### Socket.io

Авторизация: `io(url, { auth: { initData } })` (в dev — `{ devId }`).

| Событие (клиент → сервер) | Payload |
|---|---|
| `battle:start` | `{ mode: 'campaign' \| 'boss', stage? }` |
| `battle:action` | `{ battleId, skillIndex, targetUid }` |
| `battle:auto` | `{ battleId }` — авто-бой до конца |
| `battle:leave` | `{ battleId }` |

| Событие (сервер → клиент) | Payload |
|---|---|
| `battle:update` | `{ battleId, state, events, rewards? , started? }` |
| `battle:rewards` | `{ battleId, win, rewards }` |
| `battle:error` | `{ code, message }` |

**Формат `events[]`** (по ним клиент строит анимации: цифры урона, шейк, баффы):

```jsonc
{ "type": "turn",    "unit": "h_abc", "turnNo": 7 }
{ "type": "skill",   "actor": "h_abc", "skill": "Теневой выпад", "skillId": "shadow", "targets": ["m_1"] }
{ "type": "damage",  "actor": "h_abc", "target": "m_1", "dmg": 412, "absorbed": 0,
                     "crit": true, "affinity": "strong", "hp": 120, "maxHp": 520 }
{ "type": "buff",    "targets": ["h_abc"], "buff": "shield" }   // poison | defDown | shield | counter
{ "type": "counter", "actor": "h_abc", "target": "m_1" }
{ "type": "death",   "unit": "m_1" }
{ "type": "end",     "win": true }
{ "type": "rewards", "rewards": { "gold": 385, "xp": 62, "stars": 0, "items": [] } }
```

`affinity` в событии урона: `strong` (жёлто-белые цифры), `weak` (серые), `neutral` (белые),
`crit` — крупные цифры + тряска экрана.

## 7. Админ-панель

Доступна только если `tgUser.id === '8213153991'` (или ID из `ADMIN_IDS`).
В ответе `/api/state` у такого игрока `user.isAdmin === true` — клиент показывает вкладку «Админка».

| Endpoint | Payload |
|---|---|
| `GET /api/admin/user/:tgId` | поиск игрока по ID |
| `POST /api/admin/grant` | `{ tgId, gold, stars, energy, rating }` (дельты, могут быть отрицательными) |
| `POST /api/admin/item` | `{ tgId, slot, rarity, level?, setId? }` |
| `POST /api/admin/hero` | `{ tgId, key, stars, level }` |
| `POST /api/admin/ban` | `{ tgId, banned: true\|false, reason }` |

Забаненный игрок получает `403 BANNED` на REST и `AUTH_FAILED` на сокетах.

## 8. Интерфейс (`index.html`)

Один файл: разметка, CSS-токены, весь JS. Без фреймворков и без сборки.

### 8.1. Гейт: вне Telegram игра не грузится

Это первое, что выполняется — до любых запросов к API:

```js
const tg = window.Telegram && window.Telegram.WebApp;
if (!tg)                → hardStop('Игра не запущена…');
if (!tg.initData)       → hardStop('Нет данных авторизации…');
```

`hardStop()` **удаляет узел `#app` из DOM** (игра физически отсутствует в документе),
показывает экран с гербом и текстом причины и блокирует прокрутку.
Ни одного запроса к `/api/*`, ни одного socket-подключения при этом не происходит.

Проверено автоматически (`test/shots.py`): при открытии вне Telegram `#app` в DOM — **0 узлов**.

Дополнительно: если сервер вернёт `401` — тот же гейт с текстом «Не удалось подтвердить аккаунт»,
если `403 BANNED` — экран блокировки с причиной.

| Экран | Что внутри |

| **Город** | герб, состав отряда, карточки режимов, призыв за ⭐, восстановление энергии |
| **Кампания** | 12 этапов, замки, награды, состав врагов, вход в живой бой |

### 8.3. Бой

- Слева команда игрока, справа враги (зеркальные портреты).
- На юните: HP-бар с плавным убыванием, шкала хода (Turn Meter), иконки баффов.
- **Всплывающие цифры урона**: белые (обычный), золотые крупные (крит), приглушённые (слабая стихия), зелёные (яд).
- **Тряска экрана** (`CSS @keyframes shake`) при крите и сильной стихии + вибро-отклик.
- Баннер умения, лог последних действий, кнопки скиллов с маской кулдауна.
- Кнопка «Авто» доигрывает бой; если нажата во время анимации — ставится в очередь.
- Клиент **не считает урон**: он проигрывает `events[]`, присланные сервером.

### 8.4. Единственный способ сообщений — `showToast`

```js

```
`alert()`, `confirm()` и `prompt()` в проекте не используются вообще.

### 8.5. Дизайн-токены

Всё в `:root`: графит `#0A0B0E`, панели `#13161C`, золото `#C8A55B`, приглушённые
акценты стихий, рамки редкости. Никаких неоновых цветов. Заголовки — засечный системный
шрифт (Georgia), интерфейс — системный sans. Иконки — SVG из `images/`, портреты — PNG с альфой.

## 9. Безопасность

- Подпись `initData` проверяется по HMAC-SHA256 (`WebAppData` → secret → hash)
  с `timingSafeEqual`, плюс проверка свежести `auth_date` (24 ч).
  Проверено на реальном HMAC (тестовый токен): валидный → `200`, битая подпись → `401 BAD_SIGNATURE`,
  просроченный на 3 дня → `401 INIT_DATA_EXPIRED`, пустой → `401 NO_INIT_DATA`.
- Игрок никогда не присылает свои характеристики или урон — только `skillIndex`
  и `targetUid`; всё остальное считает сервер.
- Проверка «свой ли это бой» (`battle.ownerTgId`), проверка КД скилла,
  проверка блокировки этапа и наличия энергии — на сервере.
